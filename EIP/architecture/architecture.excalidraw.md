Points de défaillance identifiés ^EFEtb6F7

1. Paquet npm : un seul binaire linux-x64 (build ubuntu-latest) + wrapper bash → inutilisable sur macOS / Windows / ARM, et sur Alpine (musl) car le binaire est lié dynamiquement à la glibc ; pas de binaires par plateforme ni de fallback.
2. CI/CD : le mirror vers le repo Epitech dépend d'une clé SSH en secret (MIRROR_SSH_KEY) — clé révoquée = le mirror et la synchro du wiki s'arrêtent.
3. Détection par extension seule : .ts ambigu (Drizzle / TypeORM / …) dès le 2e ORM ; la confirmation stdin bloque en CI tant que --no-input n'existe pas.
4. Importer Prisma : syntaxe non couverte par la grammaire → ImportError global, aucune récupération partielle ni position d'erreur exploitable par l'utilisateur.
5. Export : constructs sans équivalent dans l'ORM cible → perte silencieuse s'ils ne passent pas par OrmMetadata / UnknownFeature (round-trip non garanti).
6. Évolution du pivot : chaque bump de pivot_version impose de migrer les pivots déjà stockés (file_versions.pivot) et l'historique du versioning.
7. Codemods : réécriture partielle ou fausse du code utilisateur (job « partial ») → imposer dry-run / diff et passer par une PR plutôt qu'écrire en place.
8. Serveur : crash du worker → jobs bloqués en « running » ; pas de reprise ni de timeout ; transform CPU-bound à sortir du runtime async (spawn_blocking).
9. GitHub / GitLab : tokens expirés ou révoqués, rate limits, perte de la clé de chiffrement des tokens = toutes les intégrations à refaire.
10. PostgreSQL : point unique de défaillance du mode serveur (pas de réplique, pool saturé → API down) ; quotas UsageEvent faux si le comptage n'est pas transactionnel.
11. Paiement : webhook perdu ou en retard → statut d'abonnement faux, donc quotas du Plan faux (team bloquée à tort ou quota dépassé sans facturation).
12. Serveur en instance unique : un crash ou un redéploiement coupe l'API, donc tout le front ; rien devant pour répartir la charge ou basculer. ^drL0Prag
